# Phase 7 — ERPNext Buying and Inventory Cutover

**Branch:** `main`  
**Integration site:** `ledgix-erpnext.local`  
**Framework baseline:** Frappe 15.113.4 / ERPNext 15.121.3  
**Status:** IMPLEMENTED — FINAL RUNTIME GATE PENDING

## Goal

Move new buying and inventory authority from the custom Ledgix engine to standard ERPNext documents without deleting historical Ledgix records.

## Authority after Phase 7

| Concern | Authority |
| --- | --- |
| Supplier master | ERPNext `Supplier` |
| Purchase order | ERPNext `Purchase Order` |
| Goods receipt | ERPNext `Purchase Receipt` |
| Supplier invoice / AP | ERPNext `Purchase Invoice` |
| Supplier payment | ERPNext `Payment Entry` |
| Stock receipt / issue / transfer | ERPNext `Stock Entry` |
| Quantity correction | ERPNext `Stock Reconciliation` |
| Quantity / valuation ledger | ERPNext `Stock Ledger Entry` / `Bin` |
| Batch tracking | ERPNext `Batch` + Serial and Batch Bundle |
| Serial tracking | ERPNext `Serial No` + Serial and Batch Bundle |
| Legacy purchase/stock history | retained read-only migration history until retirement phase |

## Canonical service

`ledgix_saas.services.erpnext_buying_inventory`

The service resolves migrated legacy Supplier/Item/Mode-of-Payment identities but creates only standard ERPNext documents. It never creates or mutates:

- `Ledgix Purchase`;
- `Ledgix Stock Movement`;
- `Ledgix Stock Lot`;
- `Ledgix Stock Serial`.

Client IDs stored on native documents provide Ledgix routing/idempotency context without creating a second transaction ledger.

## Purchase flows

Supported native paths:

```text
Full buying:
Purchase Order -> Purchase Receipt -> Purchase Invoice -> Payment Entry

Small-shop/direct buying:
Purchase Invoice (update_stock=1 when inventory is enabled) -> Payment Entry

Invoice-only/non-stock:
Purchase Invoice -> accounting only, no Stock Ledger Entry
```

Purchase returns use ERPNext's native return mapper against the submitted Purchase Invoice.

## Inventory flows

Ledgix manual stock compatibility now creates native ERPNext Stock Entries:

- Material Receipt;
- Material Issue;
- Material Transfer.

Stock corrections use Stock Reconciliation. Quantity and valuation reads use ERPNext `Bin` / Stock Ledger Entry.

For tracked stock:

- Batch identities are ERPNext `Batch`;
- serial identities are ERPNext `Serial No`;
- ERPNext v15 Serial and Batch Bundle is allowed to remain the authoritative bundle generated by stock controllers.

The existing POS serial-picker RPC retains its response shape but now reads available native Serial Nos.

## Supplier AP preflight

`ledgix_saas.migration.erpnext_phase7_supplier_ap_preflight.run` compares each mapped legacy supplier's current payable state to ERPNext Supplier GL state.

The legacy `opening_balance` is retained as provenance only. The preflight compares `current_balance` because Phase 7 must reconcile today's liability; it never silently reposts an old opening seed as a new payable.

Any non-zero mismatch is a cutover blocker.

## Workspace routing

The Ledgix workspace now routes Buying and Inventory operations to native ERPNext DocTypes:

- Purchase Order;
- Purchase Receipt;
- Purchase Invoice;
- Supplier;
- Item / Item Group;
- Warehouse;
- Stock Entry;
- Stock Reconciliation;
- Batch;
- Serial No.

Legacy operational reports remain available temporarily and will be reworked to ERPNext datasources in the BI/reporting phase.

## Final gate

Run:

```bash
bash scripts/run_erpnext_phase7_final_gate.sh ledgix-erpnext.local
```

The gate is main-only and restricted to the integration site. It runs:

1. local repository CI;
2. migrate / Phase 7 extension schema;
3. fail-closed Phase 6 + Phase 7 static contracts;
4. supplier AP reconciliation preflight;
5. Phase 7 buying/inventory runtime matrix.

The runtime matrix proves:

- PO -> PR -> PI -> supplier Payment Entry;
- purchase client-ID idempotency;
- direct Purchase Invoice with stock effect;
- non-stock financial-only purchase with no SLE;
- Material Transfer;
- Stock Reconciliation;
- Batch bundle behavior;
- Serial No availability and issue behavior;
- native Purchase Return;
- stock cancellation restoring quantity;
- backdated Stock Entry/SLE behavior;
- ERPNext Bin/SLE valuation authority;
- no parallel Ledgix Purchase/Stock Movement/Lot/Serial writes.

## Exit criterion

Phase 7 is complete only when the supplier AP preflight is green and the runtime result returns both:

- `phase7_complete=true`;
- `phase8_ready=true`.

After that Phase 8 migrates the retail POS engine/UI backend onto the already-proven native ERPNext transaction, stock, pricing and payment authority.
